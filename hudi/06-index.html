索引体系：record key 如何找到自己的文件组

索引是 Hudi 更新效率的命门：HoodieIndex.tagLocation() 把每条待写记录映射到它所属的 fileGroup。实现可插拔——从对象存储友好的 Bloom 到外部 KV 的 HBase，再到自管的 Record Index。

01接口与职责

图图 6-1 · 索引家族：把 record key 映射到 fileGroup 的不同实现

HoodieIndex 抽象类只要求两个能力：tagLocation（给记录打上 fileId 位置）与 updateLocation（提交后把新 key 写回索引）。是否索引 log 记录（canIndexLogFiles）、是否全局唯一（isGlobal）决定了各实现的行为分叉。

02Bloom Index：对象存储的原住民

SparkHoodieBloomIndex 先用 interval 树按 key 范围裁剪候选文件，再并行读每个文件的 bloom filter（写 base 时由 HoodieCreateHandle 写进 footer，MDT 模式下改从元数据表读取），命中者再做精确比对。代价模型由 HoodieGlobalSimpleKeyGenerator 等键生成器配合。

03Bucket 与 Record Index

HoodieBucketIndex 直接按 key 哈希到固定 bucket（一个 bucket = 一个 fileGroup），彻底跳过查找：写入路径 O(1)，代价是 bucket 数固定（ConsistentBucketIndex 用一致性哈希支持扩容）。Record Index 是新方向：把 key→location 存进元数据表，随表自愈、无需外部系统。
