Timeline：把每一次变更变成时间线上的一个点

Timeline 是 Hudi 的心跳。所有写入、compaction、clean、rollback 都是时间线上的一个 instant（动作 + 状态 + 时间戳）。理解 Timeline 的状态机与文件形态，就理解了 Hudi 的 ACID、崩溃恢复与表服务调度。

01Instant 的三要素

HoodieInstant = action（做什么：commit/deltacommit/compaction/clean/rollback/replacecommit/savepoint）+ state（做到哪：requested/inflight/completed）+ timestamp（何时：形如 20240115103000000 的字符串）。三者的组合唯一确定一次表变更。

HoodieTimeline 接口提供过滤与遍历：filterCompletedInstants()、filterInflights()、lastInstant()、nthInstant(n)、findInstantsBeforeOrEquals(ts) 等。查询路径几乎总是先取 metaClient.getActiveTimeline 再过滤 completed。

02状态机与崩溃恢复

图图 2-1 · Timeline 状态机：每个 instant 走完 requested → inflight → completed；崩溃后 inflight 可 rollback 重放

关键设计：completed 文件由 inflight 原子重命名而来。因此「存在 completed 即成功、只有 inflight 即未完成」，崩溃恢复时 Hudi 对 inflight 走 rollback（写 rollback instant）或按配置重放。HoodieActiveTimeline 的 transitionState() 与 saveAsComplete() 是状态迁移的仅有入口。

03元数据内容与 Schema

commit 文件的内容是 HoodieCommitMetadata（avro 序列化，json 兼容）：按分区汇总写入统计、每个 fileGroup 的变更、compaction/cluster 的输入输出。replacecommit 额外携带被替换删除的文件（clustering 与 partition 迁移都用它）。

时间线增长由 archival 控制：HoodieArchivedTimeline 把老 instant 打包进元数据表的归档分区，active timeline 只保留最近窗口。

04源码坐标

核心类：common/table/timeline/HoodieInstant.java、HoodieTimeline.java（接口 + 默认实现 HoodieDefaultTimeline）、HoodieActiveTimeline.java（存储 IO）。表配置：HoodieTableConfig；入口：HoodieTableMetaClient。
