读路径：Snapshot、Read Optimized 与 Incremental

同一张 Hudi 表提供三种读法，本质是对 FileSlice 的三种选择策略。查询引擎通过 InputFormat / Catalog 接入，视图层负责把「时间线上的某一刻」翻译成「一组可读文件」。

01三种查询

图图 7-1 · 三种查询：Snapshot / Read Optimized / Incremental

Snapshot Query 返回「此刻」的完整表：COW 只读最新 base；MOR 在读时合并 log（merge on read 由此得名）。Read Optimized 只读已完成 compaction 的纯 base，牺牲新鲜度换取稳定性能。Incremental Query 输出指定 instant 区间内的变更，是下游物化视图与流式管道的基础。

02视图层如何选文件

FileSystemViewManager 为每个表维护视图缓存（可本地内存或服务端化）。HoodieTableFileSystemView.getLatestFileSlices() 等方法按 latest completed instant 选取切片；ReadOptimized 则额外过滤「compaction 已完成」的切片。所有选择都以 CH02 的 timeline 为事实来源。

03引擎接入

Hive/Presto/Trino 走 hudi-hadoop-mr 的 InputFormat（Snapshot 用 Realtime 版，RO 用普通版）；Spark 走 datasource（hudi-spark-datasource）；Flink 走 hudi-flink-datasource 的连贯流读。Schema 由 TableSchemaResolver 把 avro（timeline 与日志块内嵌）映射为引擎类型。
