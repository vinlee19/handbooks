文件布局：FileGroup、FileSlice 与 Log File

Hudi 的目录布局刻意保持「分区/文件组/切片」三层：fileId 是记录的身份，commit 是切片的版本。COW 用整文件替换表达更新，MOR 用追加日志表达增量——两者共享同一套视图抽象。

01FileGroup：身份绑定

一个 FileGroup 由唯一 fileId 标识，生命周期内不换名。索引层（CH06）把 record key 映射到 fileId，从而保证「同 key 更新永远落在同一文件组」——这是 Hudi 避免全表扫描做更新的根本。

FileSlice 是 fileGroup 在某个 instant 的版本：= 一个 base file（COW 必有）+ 其后追加的所有 log file（MOR）。新 commit 产生新 slice，旧 slice 在 clean 之前仍可被 Time Travel / 增量查询引用。

02布局图解

图图 3-1 · 文件布局：FileGroup 是身份，FileSlice 是版本；MOR 在切片内追加 log

Base File 是不可变 Parquet；Log File（.log_N）由 HoodieLogFormatWriter 顺序追加，每个 block 自带头部（含 instantTime、schema、block 类型）。读取时 HoodieLogFormatReader 逐块反序列化。

03Log Block 类型

HoodieLogBlock 家族：AVRO_DATA_BLOCK（数据）、DELETE_BLOCK（整行删除）、COMMAND_BLOCK（rollback 指令）、CORRUPT_BLOCK（损坏占位）、HFILE_DATA_BLOCK。block 头部带 magic 六字节（HOODIE_MAGIC）用于扫描定位与损坏跳过。

视图层 common/table/view/ 把这些物理事实组装成逻辑视图：HoodieTableFileSystemView 按 (partition, fileId) 缓存 FileSlice，提供 getLatestFileSlice()、getLatestBaseFile() 等 API——查询与 compaction 调度都建立在它之上。
