06 · 标量索引与全文检索（FTS）

向量检索只是半个故事——生产 ANN 查询几乎总是带结构化过滤。本章解析 BTree/Bitmap/ZoneMap/NGram/RTree/Bloom 的实现与 Inverted 索引 + BM25 全文检索（词表、posting list、WAND 逐层加速），以及"索引掩码 → prefilter → ANN"的融合机制。

1. 标量索引家族

索引数据结构擅长的谓词源码

2. BTree 索引的物理形态

并行下探（每个叶子页是独立可调度单元） → 命中 row id 集 → 转 RoaringBitmap → 交并差组合（expression.rs） 索引本体用 Lance 文件格式存储；查询命中部分只需读相关页（列裁剪思想复用）

3. Inverted 索引：词表 → posting list → BM25

FTS 子系统（scalar/inverted/）是仓库中最"数据库内核"味道的部分：自带分词器框架（tokenizer/，接 lance-tokenizer crate）、打分器（scorer.rs）、WAND 分支定界（wand.rs）、复合查询（compound/：Boolean/Phrase/Boost）与跨列联合（cross_column.rs）。

图 6-2 · FTS 管线。BM25 的 IDF 来自全局统计，WAND 让 top-k 查询不必穷举全部 posting。

4. 谓词下推与 prefilter：三路融合

图 6-3 · 谓词路由。Lance 优化器（io/exec/optimizer.rs）在 DataFusion 规则之上加了 Lance 特有规则：索引替换、count 下推、zone map 感知。
ZoneMap 在哪？它不是独立索引而是随编码生成的统计（lance-encoding statistics.rs：DataBlock 层记录 min/max/null_count）。v2 文件把这些统计存在列元数据 buffer 里，pushdown 扫描用它们整页跳过——"免费的范围索引"。
建索引的通用心智模型：所有标量索引 = "把 row id 按键组织成可剪枝结构 + 用 Lance 文件存" 。区别只在键的形态（有序值/唯一值/词元/n-gram/几何框）。因此：① 索引可与数据不同 fragment 版本（fragment_bitmap 校验）；② 索引更新=重建受影响 fragment 部分；③ 一切索引查询结果都是行地址位图，进入统一的下游融合。
