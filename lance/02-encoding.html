02 · 编码体系（lance-encoding）

核心 crate（~18,400 行）：把"数据怎么切成可独立解码的小块"（结构编码）与"块内字节怎么压缩"（压缩编码）彻底解耦为两个正交维度。理解本章 = 理解 Lance 高性能的本质。

1. 总纲：类型 × 布局 正交，结构 × 压缩 正交

官方文档（docs/src/format/file/encoding.md）给出的术语体系：数组(array)是值的序列，数据类型描述语义解释，布局(layout)是把数组编码成 buffer+子数组的方案，编码(encoding)描述类型→布局的映射。Lance 的决定性设计是把这个映射拆成两层：

图 2-1 · 结构编码决定"随机访问"，压缩编码决定"体积/CPU"。任何压缩算法只要遵守 DataBlock 契约即可插入，无需理解 page/miniblock —— 这就是"吸干 I/O 细节"的架构含义。
为什么必须分层？想象一个 string 列：FSST 压缩算法不该关心"这一页里第 7 个 miniblock 从哪开始"；而 MiniBlock 布局不该关心"这个块的 zlib 参数"。两层各自独立演进：v2.3 加入 Sparse 布局时，BitPack/FSST 内核一行不改。对照 Parquet：其 page header 内嵌编码+压缩选择，扩展编码必须动格式规范。

2. 结构布局逐个击破

2.1 MiniBlock —— 默认布局（小值）

适用整数/浮点/布尔/短字符串等"小类型"。Page 被切成若干 miniblock：每块值数为 2 的幂（最后一块除外），压缩后 <32KiB，8 字节对齐。随机访问一行只需读 1 个 miniblock（1 次 IOP）。

图 2-2 · MiniBlock 布局字节细节（依据 docs/src/format/file/encoding.md 与 encodings/logical/primitive/miniblock.rs）。

2.2 FullZip —— 大值布局（≥256 字节，典型：向量嵌入）

值大到"每 16 个值就要一个 miniblock 描述符"太浪费时（官方阈值 256 字节），改用 FullZip：所有 buffer 压缩成一个缓冲区，值与值逐位 zip 在一起。代价是随机访问可能要 2 次 IOP（先查 repetition index 再取值），换取 page 内零"块开销"。

纯平坦 buffer，完美对齐 SIMD。 约束：压缩必须"透明"（压缩后仍能定位单个值）→ 禁止 delta 等 opaque 方案。 源码：encodings/logical/primitive/fullzip.rs Buffer 1：Repetition Index（可选） 行0 偏移 u64 行1 偏移 u64 每行 1 个 u64 → 该行在 Buffer0 的起始偏移。 固定宽 1/2/4/8B 字节打包；不整体压缩。 随机访问：IOP1 读 index → IOP2 读值。 全量扫描读法：整个跳过 Buffer1。 与 KNN 的化学反应：768 维 f32 向量 = 3072B ≫ 256B → 每页存 16 个向量（8MiB page）， 解码后是连续对齐的 f32 数组 → 直接进 lance-linalg 的 AVX2/AVX-512 距离内核（见 07 篇），全程零拷贝。
图 2-3 · FullZip 布局。向量列在 Lance 里的真实落盘形态几乎就是"裸的 SIMD 就绪数组"。

2.3 Constant / Blob / Sparse

布局触发条件物理形态妙处
Constant页内全部值相同（常见：全 null 列、枚举段）值内联在 proto 描述里（v2.1 只允许全 null 内联），页零 buffer读 100 万行 null = 0 字节 I/O
Blob超大值（图像/音频/长文档）页级布局内嵌 inner layout，支持 descriptor 布局（v2.2 避免在 footer 暴露逻辑子字段）；可外置到独立 blob 文件take_blobs 单值读取不打扰主数据页
Sparse (v2.3+)结构极稀疏：嵌套深度大、大多数行为空、或单行超出 dense RepDef 预算放弃密集 rep/def 流，改用槽位域映射：每层 layer=validity/list/fsl，位置集为 empty/all/range/explicit(delta 压缩 u64)，计数集为 empty/constant/explicit1 万行中只有 10 行非空时，不用写 1 万个 rep/def 事件；显式请求 lance-encoding:structural-encoding=sparse

Sparse 的 4 种位置集表示与 2 种 validity 极性（NULL_POSITIONS/VALID_POSITIONS）是 wire contract：读端必须同时支持两种极性。层序从外到内，终态子域大小 = num_visible_items（null 叶子也算）。

5. 写入端源码结构：三个 trait 撑起整个体系

// rust/lance-encoding/src/encoder.rs —— 精简后的调用链

pub trait FieldEncodingStrategy   // ① 决策层：一个 Field 用什么编码器？
  -> create_field_encoder(field, column_index, ctx) -> Box<dyn FieldEncoder>

pub trait FieldEncoder            // ② 编码层：接收 Arrow 数组流，吐出 EncodedColumn
  -> maybe_encode_batch(...) -> Vec<BoxFuture<EncodedColumn>>   // 并行！
  -> flush(...) -> Vec<BoxFuture<EncodedColumn>>
  -> finish(...) -> BoxFuture<(EncodedColumn, Option<EncodedBatch>)>

pub trait ArrayEncoder            // ③ 物理/结构执行层：DataBlock → 压缩 buffer
  -> encode(data: dyn ArrayRef, ...) -> Result<EncodedArray>

为什么编码器要在"列"粒度并行？

FieldEncoder::maybe_encode_batch 返回的是 Vec<BoxFuture> —— 每列每批的编码是一个独立 future，由 tokio 并发调度。大 batch 会被切片：MiniBlock 布局下每 32KiB 左右切一个 miniblock 并立即压缩、立即外发（流式），内存中不积累整个 page。写路径因此天然背压：I/O 慢→编码暂停→上游停读。

编码选择器怎么决策？（CoreFieldDecoderStrategy / compression_config.rs）

数据特征选择
向量列（定宽 ≥256B）FullZip + Flat（SIMD 就绪）
普通定宽数值列MiniBlock + InlineBitpacking（默认）；可配 OutOfLine
字符串列MiniBlock + Variable；重复度高→Dictionary；高熵→FSST
列式结构体（同读多列）PackedStruct（并排打包，一次 IOP 取整行）
全 null/常量页ConstantLayout
极稀疏嵌套（v2.3）Sparse 布局（dense RepDef 预算超限时自动切换）

用户可通过 field metadata / 表 config 覆盖：lance-encoding:structural-encoding、lance-encoding:dict-values-compression 等键（compression_config.rs）。

一图流总结：类型决定"值的大小"→ 大小决定"结构布局"→ 布局决定"块边界"→ 边界交给压缩编码去填充。每一层都只做一件事，这就是 02 篇想让你带走的全部。
