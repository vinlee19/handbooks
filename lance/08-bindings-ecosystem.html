PyO3 边界的关键设计

机制说明

3. Session 与缓存体系

跨查询共享的运行时状态集中在 lance::Session（session.rs）：

缓存内容默认策略
index cacheIVF 质心、HNSW 图页、标量索引页条目数或字节上限（index_cache_size_bytes）
metadata cachemanifest、文件 footer、列元数据metadata_cache_size_bytes
fragment/file sessionFragmentSession（dataset/fragment/session.rs）绑定 open 文件句柄与 footer 缓存随 Dataset 生命周期
I/O scheduler 池每 ObjectStore 一个 ScanScheduler（03 篇）io_parallelism 深度

Python 侧 lance.Session(index_cache_size_bytes=…) 可注入多个 Dataset 共享——多表 RAG 场景的关键调优点。缓存按 ObjectStore 维度隔离，避免跨 bucket 污染。

5. 测试与质量基建（学习源码的第二条路径）

设施位置作用
test_data/ 数据集仓库根，配 datagen.py老版本写的数据集入库，保证向后兼容读取（CLAUDE.md 的规定流程）
lance-testing / lance-test-macrosrust/公共测试工具、参数化宏
integration testspython/tests/test_s3_ddb.py + docker-composeMinIO(S3)+DynamoDB 仿真，跑真实对象存储提交路径
benchmarks/python/benchmarksKNN/扫描端到端基准（test_knn.py 等）
memtest/仓库根内存占用回归
testing.rs（各 crate）如 lance-encoding/src/testing.rs（1572 行）随机数据+随机读取模式，编码器/解码器 fuzz 式互验
给学习者的建议路线：① 读 protos/ 全部 proto（格式规范）→ ② 读 docs/src/format/（官方规范文档，比源码注释更系统）→ ③ 沿 03/04 篇的调用栈打 Rust 断点 → ④ 用 lance-encoding/src/testing.rs 的随机框架做实验 → ⑤ 改一行编码选择逻辑，diff 文件字节观察变化。这一套走完，你对 Lance 的理解会超过绝大多数贡献者。
