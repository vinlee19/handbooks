managed ingestion engine for Apache Iceberg — 为 Iceberg 湖仓带来毫秒级流式写入

Moonlink 解决的核心矛盾是：Iceberg 表格式擅长大规模批式分析，却不擅长高频流式写入。传统摄取工具每来一批更新就往对象存储写小 Parquet 文件 + equality-delete 文件，很快陷入「小文件泛滥 → 元数据爆炸 → 读性能劣化 → 依赖 Spark 做合并」的泥潭。Moonlink 的答案是把「写入缓冲、索引、删除」放在本地 NVMe 内存态里做，只把「大小合适的 Parquet + Iceberg v3 Deletion Vector」异步暴露给 Iceberg——本系列 9 章将带你把这条链路彻底拆开。
