Chapter 04 · 双层索引与 Deletion Vector

主键索引决定「DELETE 能不能 O(1) 定位」，删除向量决定「ICEberg 读侧怎么知道哪些行没了」。这一章是 moonlink 最有原创性的部分。

4.1 双层索引总览

索引随着数据的位置分两层：MemIndex 管内存里的行，GlobalIndex（FileIndex）管已经 flush 成文件的行。两层都是「主键哈希 → RecordLocation」的哈希结构，flush 时从一层「重映射」到另一层。

4.4 索引合并（index merge）与 compaction 的关系

设计闭环：flush 越多，GlobalIndex 的 block 越碎 → 查询要归并的 block 越多 → moonlink 用「把小 index block 合并成大 block」的方式整理索引（FileIndexMergeConfig：16–32 个未满 512MiB 的 block 触发）。合并索引必然涉及「重写索引指向的数据文件」的配合，所以与 data compaction 同一个快照周期只允许一个在途（BackgroundTaskStatus 串行化），避免重映射打架。
