Chapter 08 · 控制面：MoonlinkBackend、元数据仓与服务入口

数据面是每表的 actor 世界，控制面则回答「有哪些表、从哪来、怎么恢复」。moonlink_backend 是所有入口（REST/RPC/OTEL）的唯一编排者。

8.1 MoonlinkBackend：唯一的编排者

moonlink_service 启动时构造一个 MoonlinkBackend（src/moonlink_backend/src/lib.rs），此后 REST handler、RPC server、OTEL handler 全部只跟它对话。它持有三样东西：ReplicationManager（数据源连接）、metadata_store_accessor（表清单）、两个路径重映射闭包。

8.2 端点全景：REST 与 RPC

图 8-2 · 全部对外端点（rest_api.rs create_router + moonlink_rpc rpcs! 宏，与源码逐条核对）
为什么同时要 REST 和 RPC 两套？REST 面向「数据与运维」（人类友好、可 curl、K8s 探活），RPC 面向「查询引擎」（二进制高效、长连接、语义精确的 begin/end 配对）。OTEL 那个端点则是展示野心的一笔：moonlink 把自身的运行指标当数据流摄入自己的 Iceberg 表——用产品吃自己的狗粮。

8.4 存算分离：路径重映射

两个闭包（moonlink_backend/lib.rs 构造时注入）：read_state_filepath_remap 把 ReadState 里的本地文件路径换成 data server URI；http_filepath_remap 用于 parquet metadata 查询。moonlink 进程仍管本地缓存与写入，但「数据的规范地址」可以指向独立的数据服务 —— moonlink_datafusion 连接远端 moonlink 时拿到的就是公网可取的 URL。这是部署在 K8s（deploy/）里多副本/远端查询形态的基础。
