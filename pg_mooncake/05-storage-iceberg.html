存储与 Iceberg 持久化：Parquet、Puffin 与开放表格式

这一章讲数据“落地”的全部细节：内存批怎么写成 Parquet、删除怎么变成 Puffin 里的 Roaring 位图、每次快照怎么成为一次真正的 Iceberg 提交、以及崩溃之后怎么把世界拼回来。

5.1 持久化全景：两个“快照”、一次提交

先厘清贯穿全章的两个概念：mooncake 快照是引擎内存里的版本推进（磁盘文件集合 + 内存批 + 删除向量的自洽组合）；Iceberg 快照是把某个 mooncake 快照持久化为开放格式（写 manifest、提交 catalog）。前者频繁且廉价，后者昂贵且攒批——两者由 LSN（moonlink.table-flush-lsn 属性）关联。

图 5-1 · 持久化四段式：内存 → 本地 Parquet/索引 → Iceberg 导入与 Puffin 附件 → Catalog 提交

fn write(&mut self) {
    for batch in self.record_batches {          // 已抽干的 MemSlice 批
        let batch = apply_deletions(batch, &deletion_vector);  // 物理剔除已删行
        writer.write(batch).await;               // AsyncArrowWriter 追加
        if writer.in_progress_size() >= 128.MiB { // parquet_file_size（debug 下 2MiB）
            let file = writer.close().await;     // 切换新文件 → data_<n>.parquet
            index_builder.record_file(file, row_range);
        }
    }

}
  • 删除物理应用：flush 时把“这些行已删除”从 Parquet 里剔掉，避免每个读者都重复过滤（删改先记账在删除向量，落盘时清算）。
  • 文件索引：row_id → (file, row_offset) 的持久化桶哈希表。UPDATE = 旧行删除向量标记 + 新行插入新位置，索引让“点查/回改”不必全表扫描。它也被同步为 Puffin blob（5.3），使外部引擎可复用。
  • flush 完成记账：FlushResult 事件回流 → apply_flush_result（:959）把 disk slice 加入 next_snapshot_task.new_disk_slices → try_set_next_flush_lsn（:985）推进 flush 水位。

🔑 兼容性博弈 数据文件是 100% 标准 Iceberg（任何 Iceberg 引擎都能读 Parquet 行）；moonlink 的增量价值（删除向量、索引、亚秒新鲜度）都在 Puffin 附件与快照属性里——不理解它们的普通 Iceberg 读者会读到“略旧但完整”的数据，这本身就是一种优雅的降级。
