端到端数据流：五条链路串起整个系统

前面五章的零件，在这里装配成整车：CREATE、INSERT、SELECT、DROP、崩溃恢复——每条链路一张完整泳道图，最后用 LSN 不变式收束全局。

图 7-1 · CREATE 链路：借道 SQL 建空壳表 → RPC 注册 → 复制流启动

7.2 INSERT：一行数据的完整旅程（写入→可查）

图 7-2 · INSERT 链路：WAL → 事件 → 内存 → Parquet → 快照 → 湖仓，五级水位逐级推进
💡 新鲜度从哪来 即使 flush/快照还没发生，内存数据也已对扫描可见——Union Read 会把“已提交未落盘”的行物化成临时 Parquet 一并交给 DuckDB。所以新鲜度只受复制延迟影响（通常毫秒级），不受落盘节奏影响。

7.5 全局收束：LSN 不变式

图 7-5 · LSN 不变式：写入照它推进，扫描照它等待，恢复照它补齐
🔑 全书收束 pg_mooncake 的所有机制——空壳 AM、进程内 bgworker、bincode RPC、文件直读、Puffin 附件、压缩搭车、WAL 三层恢复——都是在为这一条不等式服务：用一条 LSN 流水线，同时解决“新鲜、一致、可恢复”三件事，且互不阻塞。
