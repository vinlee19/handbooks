pg_mooncake：把 Iceberg 湖仓装进 Postgres

pg_mooncake 是一个 Postgres 扩展，为表创建 Iceberg 列存镜像（columnstore mirror）：写入侧通过 moonlink 引擎以逻辑复制近实时摄取变更并落成 Parquet；查询侧借助 pg_duckdb 把 SQL 强制路由进内嵌 DuckDB，以亚秒级新鲜度直接扫描湖仓文件。本系列文档从 0 到 1 拆解它的原理、架构与底层源码。

~940 行Postgres 扩展层 Rust 代码（src/）
12 个 cratemoonlink 湖仓引擎（Rust 工作区）
C++ 扩展duckdb_mooncake（DuckDB 存储扩展）
35+ 张图本系列手绘架构 / 时序 / 原理图

一、物理架构总图

先记住这张图——它是整个项目的“地图”：一切发生在同一个 Postgres 进程里。每个后端连接加载 pg_duckdb.so 与 pg_mooncake.so；一个常驻的 background worker（名字就叫 moonlink）承载整个湖仓引擎；两者之间用 Unix Domain Socket 上的 bincode RPC 通信；数据不经过 RPC 传输——moonlink 把 Parquet/Puffin 文件写到 $PGDATA/pg_mooncake/，DuckDB 按文件路径直接读取。

图 0-1 · pg_mooncake 物理架构总图：单 Postgres 进程内的三层分工（扩展层 → moonlink 引擎 → 磁盘/湖仓）
🔑 一句话架构 控制面走 RPC（建表、删表、快照、扫描元数据），数据面走文件系统（Parquet 直读），一致性靠 LSN 单一时钟（Postgres 的 XactLastCommitEnd 贯穿写入与查询两条链路）。
