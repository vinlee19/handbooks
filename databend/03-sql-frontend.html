03 · SQL 前端：词法 / 语法 / 绑定

基于 commit fe693bb677。本篇覆盖 databend-common-ast 与 databend-common-sql::planner::binder，把 SQL 文本变成 Plan。

1. 解决了什么问题

现代分析型数据库的 SQL 前端不只是「把字符串 parse 成 AST」。它要解决三件事：

  1. 方言：兼容 MySQL/PostgreSQL/Hive，关键字、引号风格、可选分号都不同。
  2. 错误恢复：用户经常写一半 SQL 就求补全；前端必须给出位置精准、可读的错误。
  3. 语义校验前置：列引用是否唯一、子查询能否解相关、聚合表达式能否出现在投影里——这些得在生成逻辑计划之前就结束。

直接用 sqlparser 这类库的反例：

反例 问题
用 sqlparser 通用 AST 关键字方言、字段精度（如 Decimal/Variant/Geo）不够细
把语义校验留给优化器 优化器要做的事被绑定细节污染；错误信息只能指向「列不存在」而无法精确到 token
把 Bind 放进 Interpreter 子查询、CTE、相关引用没法在统一上下文里解析

Databend 的取舍：手写 nom parser + 独立的 Binder 阶段输出 (SExpr, BindContext)，逻辑和物理计划之后才出场。

3. 关键数据结构

3.1 Tokenizer 与 nom Parser

Databend 用 nom（parser combinator）手写LL(无限回溯) parser，对应 src/query/ast/src/parser/parser.rs::parse_sql (L≈48)：

// src/query/ast/src/parser/parser.rs:42
pub fn tokenize_sql(sql: &str) -> Result<Vec<Token<'_>>> { ... }

// src/query/ast/src/parser/parser.rs:48
pub fn parse_sql(tokens: &[Token], dialect: Dialect)
    -> Result<(Statement, Option<String>)> {
    let stmt = run_parser(tokens, dialect, ParseMode::Default, false, statement)?;
    // ...
    Ok((stmt.stmt, stmt.format))
}

run_parser (L≈156) 是统一的入口：

flowchart TB Sql[SQL 字符串] --> Tokz[Tokenizer\nparser/token.rs] Tokz --> Tokens["Vec&lt;Token&gt;"] Tokens --> Input[Input { tokens, dialect, mode, backtrace }] Input --> Combo[nom 组合器 statement / expr / values / ...] Combo --> Stmt[Statement / Expr / Values] Combo --> Bt[Backtrace 用于错误展示] Stmt --> Out["(Statement, Option&lt;FORMAT&gt;)"]

关键设计：

  • Backtrace：解析失败时不直接报错，而是在 Backtrace 里记录"最深成功位置 + 期望的 token 集合"，由 display_parser_error (L≈186) 渲染成「expected FROM, WHERE, ... at line 3 col 8」。
  • 方言：Dialect 决定关键字保留集与引号字符（双引号 vs 反引号）。parse_cluster_key_exprs (L≈117) 还会显式 fallback 到 Dialect::default()，因为 cluster key 是持久化的，跨 session 必须可读。
  • #[cfg(debug_assertions)] assert_reparse (L≈195)：debug build 下，每次 parse 完都把 AST 转回 SQL 再 parse 一次，确保 AST 是「可印刷的」——这是 Databend 维护「format SQL」能力（mod ast::format）的隐性成本。

ColumnBinding (column_binding.rs::L≈25) 是"绑定"概念的具体载体：每个出现在 SQL 中的列引用最终被解析成一个 ColumnBinding.index（Symbol）。Symbol 是个 IndexType，整个查询里全局唯一——这是后面优化器进行列裁剪、列等价、列依赖分析的基础。

注意 in_grouping 这种"小布尔"——它决定了 SELECT a, sum(b) FROM t 中的 a 是否合法（必须在 GROUP BY 中）；这种校验放在 binder 里是 OLAP 系统的标配。

4. 关键流程

4.1 整体流程

flowchart TB Sql[SQL 文本] Sql --> T[tokenize_sql] T --> P[parse_sql → Statement] P --> B0[Binder::bind] B0 --> BS[bind_statement] BS -- Query --> BQ[bind_query] BS -- DDL --> BD[bind_ddl] BS -- Insert/Replace/Merge --> BM[bind_mutation] BS -- Set / Use / Show --> BSh[bind_admin] BQ --> BSel[bind_select] BSel --> BTR[bind_table_reference] BSel --> Scal[bind scalar / aggregate / window / srf] BSel --> Proj[project / sort / limit / having / qualify] Proj --> SE[SExpr 树] SE --> P_OUT[Plan::Query { s_expr, metadata, bind_context, ... }]

Binder::bind (binder.rs::L≈144) 的实现一目了然：

// src/query/sql/src/planner/binder/binder.rs:144
pub async fn bind(mut self, stmt: &Statement) -> Result<Plan> {
    let mut bind_context = BindContext::new();
    let plan = self.bind_statement(&mut bind_context, stmt).await?;
    self.bind_query_index(&mut bind_context, &plan).await?;  // 决定可用索引
    Ok(plan)
}

bind_statement (L≈158) 是一个 ~100 个 arm 的大 match，每个 arm 把对应的 Statement variant 派发到专门的 bind_* 方法。其中 Statement::Query 走 bind_query (binder/bind_query/bind.rs)：

// 节选自 binder.rs:165
Statement::Query(query) => {
    let (mut s_expr, bind_context) = self.bind_query(bind_context, query)?;
    (s_expr, _) = self.construct_expression_scan(&s_expr, self.metadata.clone())?;
    let formatted_ast = if self.ctx.get_settings().get_enable_query_result_cache()? {
        Some(stmt.to_string())   // 用规范化 SQL 字符串作 result cache key
    } else { None };
    Plan::Query {
        s_expr: Box::new(s_expr),
        metadata: self.metadata.clone(),
        bind_context: Box::new(bind_context),
        rewrite_kind: None,
        ignore_result: query.ignore_result,
        formatted_ast,
    }
}

注意 formatted_ast —— result cache 的 key 来自 AST 重新打印的规范化 SQL，不是原始字符串。同样语义不同写法的两条 SQL 命中同一缓存。

4.2 SELECT 的内部分解

bind_select (bind_query/bind_select.rs::L≈398) 把一条 SELECT 拆成一连串 RelOperator：

flowchart LR S[SELECT a, sum(b) FROM t WHERE c>1 GROUP BY a HAVING sum(b)>10 ORDER BY a LIMIT 5] S --> FROM[bind_table_reference\n→ Scan(t)] FROM --> WHERE[bind WHERE\n→ Filter(c>1)] WHERE --> SCAN[scan AggregateInfo / WindowInfo / SetReturning\n（来自 SELECT/HAVING/QUALIFY）] SCAN --> AGG[bind_aggregate\n→ Aggregate{group_items=[a], agg_funcs=[sum(b)]}] AGG --> HAV[bind HAVING\n→ Filter(sum(b)>10)] HAV --> WIN[bind windows\n→ Window 算子若有] WIN --> Q[bind QUALIFY 若有] Q --> P[bind_projection\n→ EvalScalar / Project] P --> ORD[bind_order_by → Sort] ORD --> LIM[bind_limit → Limit] LIM --> SE[最终 SExpr]

bind_select_source (L≈132) 处理 FROM 子句：表 / 子查询 / TableFunction / VALUES / Stage 文件。每条路径都返回一个 (SExpr, BindContext)：BindContext 中的 columns 就是这一层可见的列绑定。

4.3 命名解析

sequenceDiagram participant E as Expr::ColumnRef("t.x") participant Resolver as TypeChecker (scalar/...) participant BC as BindContext participant P as parent BindContext participant Meta as Metadata E->>Resolver: resolve_column("t.x") Resolver->>BC: 查 columns[] 中 (Some("t"), "x") alt 找到 + 唯一 BC-->>Resolver: ColumnBinding else 未找到 → 向外层 Resolver->>P: 查 parent.columns[] alt 找到（外层） P-->>Resolver: 标记为 outer ref else 仍未找到 P->>Meta: 是否是 internal/virtual 列？ Meta-->>Resolver: ColumnBinding 或 ColumnNotFound end else 找到但模糊 BC-->>Resolver: AmbiguousColumn 错误 end Resolver-->>E: ScalarExpr::BoundColumnRef

外层引用（correlated subquery）在 binder 里被显式标记，不在这里解相关——解相关由优化器的 subquery_decorrelator 完成（详见 04 文档）。Binder 只负责打标签。

4.4 「未知函数」如何处理

have_udf_script / have_udf_server / udf_cache 这三个字段揭示了一个细节：Binder 解析 UDF 时会缓存定义，避免一条 SQL 内多次访问 meta-service。bind_query_index (L≈150) 是绑定结束后单独的一步——它根据当前 plan 反查可用的 inverted/vector 索引，把 inverted_index_map / vector_index_map 填好，给优化器留信息。

Databend 的 ColumnBinding 跟 DuckDB 几乎一致；而 nom 手写比 ANTLR4 慢一些但错误信息更可控，对方言切换更友好。

7. 端到端案例

SELECT count(*) FROM t WHERE x > 1，前端段：

sequenceDiagram autonumber participant T as Tokenizer participant P as parse_sql participant B as Binder::bind participant BC as BindContext participant Cat as CatalogManager participant M as Metadata T->>T: ["SELECT", "count", "(", "*", ")", "FROM", "t", "WHERE", "x", ">", "1"] T->>P: tokens P->>P: run_parser(statement) P-->>B: Statement::Query(Query { body: SELECT, where: x>1 }) B->>BC: 新建空 BindContext B->>B: bind_statement → bind_query → bind_select B->>Cat: 查 default.t Cat->>M: 注册 Table(t), Column(x), 隐式 Column(_row_id) Cat-->>B: TableInfo B->>BC: 添加 columns: [t.x → Symbol(0), ...] B->>B: bind WHERE → Filter(BoundColumnRef(0) > 1) B->>B: bind_projection: count(*) 是聚合，进入 AggregateInfo B->>B: bind_aggregate → Aggregate { group_items: [], agg_funcs: [count] } B->>B: 最终 SExpr = EvalScalar(Aggregate(Filter(Scan(t)))) B-->>P: Plan::Query { s_expr, metadata: M, bind_context: BC, ... }

注意几个细节：

  • count(*) 不需要绑定到具体列——它在 AggregateInfo 里被识别为「count of rows」，由聚合阶段直接读 BlockMeta.row_count 求和（详见 06 文档）。
  • WHERE 子句用的是 BoundColumnRef(Symbol)，不是字符串名 "x"——Symbol 才是优化器的"列等价"主键。
  • metadata 跨整个查询共享一份，子查询创建子 BindContext 但不分裂 metadata。
