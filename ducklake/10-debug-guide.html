§10.2构建三步曲与产物

# 1. 子模块（duckdb 内核 + CI 工具链）
git submodule init && git submodule update

# 2. 拉取扩展依赖模板
make pull

# 3. 编译（默认 debug；release 加 GEN=ninja release）
make
# 可选：ENABLE_SQLITE_SCANNER=1 / ENABLE_POSTGRES_SCANNER=1 打包对应后端
产物路径用途
DuckDB shell（内嵌 ducklake）build/debug/duckdb日常调试主战场
SQLLogic 测试 runnerbuild/debug/test/unittest跑 540 个 .test 文件
可分发扩展build/debug/extension/ducklake/ducklake.duckdb_extensionLOAD 进任意 DuckDB
 
# 起一个实验库
./build/debug/duckdb
ATTACH 'ducklake:meta.db' (DATA_PATH 'data/lake');
CREATE SCHEMA demo; USE demo;
CREATE TABLE t (id BIGINT, v VARCHAR);
INSERT INTO t VALUES (1,'hello'),(2,'ducklake');
SELECT * FROM ducklake_snapshots('meta_db');
SELECT * FROM t AT (VERSION => 1);
🧰 vcpkg 依赖
roaring（删除向量位图）经 vcpkg.json 声明，CMake find_package(roaring) 引入——首次构建会自动拉取。

§10.3SQLLogic 测试与配置矩阵

测试主体是 test/sql/ 下 540 个 sqllogic 文件，同一套 SQL 会在不同配置下参数化重放：

配置（test/configs/）变体内容
attach_ducklake.json把 DuckDB 核心测试库换成 DuckLake（最大覆盖面）
postgres.json / sqlite.json元数据库换成 PG / SQLite（需 docker-compose 起服务，scripts/）
deletion_vectors.json开 puffin 删除向量模式
no_inline.json关闭数据内联
minio.json数据路径走 MinIO S3
ducklake_version.json钉住旧格式版本（迁移路径）
 
# 全量测试（默认配置）
make test

# 单文件
./build/debug/test/unittest "test/sql/time_travel/timetravel.test"

# 指定配置矩阵（如 PG 后端）
./build/debug/test/unittest --test-config test/configs/postgres.json "[sql]"

# 按目录过滤
./build/debug/test/unittest "[compaction]"

§10.5调试路径 A：一条 SELECT 为什么读了这个文件

# lldb（macOS）或 gdb 同理
lldb ./build/debug/duckdb
(lldb) br set -f ducklake_metadata_manager.cpp -l 1866   # GetFilesForTable：看生成的 SQL 与候选文件
(lldb) br set -f ducklake_multi_file_reader.cpp -l 458   # MapColumns：看 field_id 如何对上物理列
(lldb) run

-- 配合 SQL 观测
SELECT * FROM ducklake_list_files('lake') ;           -- 账本里的文件
SELECT * FROM ducklake_snapshots('lake');             -- 当前快照
EXPLAIN SELECT * FROM t WHERE id = 42;               -- 看扫描算子与过滤下推

关注点：1866 行处把 filter_info 翻译成 WHERE 片段，是验证"谓词是否真的下推到文件裁剪"的唯一现场；MapColumns 处检查 column_map 可发现 schema evolution 映射错误。

§10.6调试路径 B：写冲突与重试

# 两个终端各起一个 shell，ATTACH 同一个元数据库
# 会话1 与 会话2 各自 BEGIN; INSERT …;
# 让会话2 后 COMMIT，观察重试：

(lldb) br set -f ducklake_transaction_state.cpp -l 1918  # Commit 进入
(lldb) br set -f ducklake_transaction_state.cpp -l 142   # CheckForConflicts 命中点
(lldb) br set -f ducklake_transaction.cpp -l 1351        # RetryOnError 判定

关注点：冲突分类是否如 CH 06 §6.5 矩阵预期；退避公式 wait × rand(0.5~1.0) × backoff^i（transaction_state.cpp:1994）；重试耗尽时 CleanupFiles() 是否把已写 Parquet 清干净。

-- 观测工具
SELECT * FROM ducklake_snapshots('lake') ORDER BY snapshot_id DESC LIMIT 5;
SELECT snapshot_id, commit_message FROM ducklake_snapshots('lake');

§10.7调试路径 C：内联、flush 与 compaction

(lldb) br set -f ducklake_inline_data.cpp -l 80            # Execute：截留判定
(lldb) br set -f ducklake_inline_data.cpp -l 122           # FinalExecute：超限转型
(lldb) br set -f ducklake_flush_inlined_data.cpp -l 281    # GenerateFlushCommand
(lldb) br set -f ducklake_compaction_functions.cpp -l 284  # GenerateCompactions
-- 内联实验脚本
SET ducklake_default_data_inlining_row_limit = 5;
CREATE TABLE small_t (a INT);
INSERT INTO small_t VALUES (1),(2),(3);          -- 内联（0 个 parquet）
SELECT * FROM ducklake_list_files('lake');       -- 确认无文件
CALL ducklake_flush_inlined_data('lake');        -- 手动刷盘
SELECT * FROM ducklake_list_files('lake');       -- 出现 ducklake-*.parquet
