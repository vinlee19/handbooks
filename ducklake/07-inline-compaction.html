§7.1数据内联：小表的零文件之路

为一张只有 5 行的维表写一个 Parquet 文件是纯浪费。DuckLake 让低于行数阈值的小表数据直接存进元数据库的表里——INSERT 全程不碰对象存储。

§7.4Compaction 的两种模式

ducklake_merge_adjacent_files（:949）ducklake_rewrite_data_files（:976）
目标合并时间相邻的小文件，消除写放大碎片消除删除痕迹：重写被 delete 大量污染的文件
输入选择相邻且 schema 兼容（can_merge_into_latest :306-328）的小文件；newer_than 只看新提交（:295，SQL 过滤 metadata_manager.cpp:2409-2419）按 delete_ratio 估剩余行数，超过 rewrite_delete_threshold（默认 0.95，:817-818）的重写
输出更少更大的 data_file，无 delete 残留合并净数据新文件；旧文件 + delete 文件全部退役
统计重算 per-file 统计 → RecomputeGlobalStatsAfterRewrite（transaction_state.cpp:844）聚合表级
提交记录WriteMergeAdjacent :5226 / WriteDeleteRewrites :5270（compaction 也走事务，与并发 DELETE 互斥见 CH 06 §6.5）

🔗 内联与 compaction 的联动
flush（§7.3）产出的第一批小 Parquet 正是 merge_adjacent_files 的典型输入。推荐的运维节奏：写入 → 小表自动内联 → 达阈值 flush → 定期 merge 相邻文件 → 删除多的表定期 rewrite。全部环节都是普通 SQL 函数，可用任意调度器编排。
