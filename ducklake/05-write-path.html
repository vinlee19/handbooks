§5.3分区 transform

分区方案存于 ducklake_partition_info/_column，表达式生成在 ducklake_partition_data.cpp:94-118（GetPartitionSQLExpression），绑定执行在 :283-306（ApplyPartitionTransform）：

Transform目录段示例分区表达式（写入时计算）说明
identityregion=us/直接引用列分区列直接写入 Parquet（write_partition_columns=true）
bucket(n, col)col_bucket=3/murmur3_32(col) % n哈希桶；标量函数 murmur3_32 与 Iceberg 兼容（ducklake_murmur3.cpp:102）
year/month/day/hourts_day=2026-08-29/date_diff('year', DATE '1970-01-01', ts) 等 epoch 差时间截断（IsEpochTransform :67 / GetEpochTransformPart :79）
📐 非恒等变换的关键细节
bucket/时间分区不把派生列写进 Parquet（write_partition_columns=false）：COPY 管道里通过 projection list 计算分区值用于目录命名；读取时分区值从目录段反解、按需合成虚拟列。identity 分区列则真实存在文件中。

§5.7MERGE INTO

DuckLakeCatalog::PlanMergeInto（ducklake_merge_into.cpp:621）把 MERGE 展开成"match 检测 → 按 MATCHED/NOT MATCHED 分别构造 UPDATE（删+写）与 INSERT 管道"。要点：

  • 源与目标 join 后，命中行走 UPDATE 管道（同 §5.5），未命中源行走 INSERT 管道（同 §5.1）；
  • 目标表中"被 join 命中"的 rowid 收集为删除文件——一条 MERGE 产生的新数据文件 + 删除文件在同一个事务里原子提交；
  • 与并发 DELETE/compaction 的冲突在提交时由冲突检测兜底（CH 06）。
