Iceberg 是开放的表格式（table format）：它不是数据库，而是一套关于"如何用不可变文件 + 分层元数据 + 指针交换来管理海量数据表"的协议。Catalog 存一个指针，metadata.json 记全量状态，manifest-list/manifest 做增量记账，数据文件永远不可变。

三、五条核心原理

1. 指针交换即事务

提交 = 写新 manifest-list + 写新 metadata.json + 目录 CAS。Hive 比对表参数、JDBC 用一条 UPDATE ... WHERE metadata_location = old、Glue 用 VersionId、DynamoDB 用条件写、REST 用 requirements 断言（AssertRefSnapshotID）、Hadoop 干脆用文件系统原子 rename。Catalog 只保证指针原子性，其余正确性由乐观重试与校验保证。

2. 乐观并发：追加永不冲突

FastAppend/MergeAppend 没有 validate 覆写——并发 append 全部成功，后到者重放一次即可。OverwriteFiles/RowDelta/DeleteFiles 显式声明校验（validateNoConflictingDataFiles 等），冲突范围 = 起始快照之后的对应操作清单 ∩ 冲突检测过滤。失败抛 CommitFailedException（指数退避重试 ×4）；500/502/504 视为 CommitStateUnknown，先 checkCommitStatus 复核目录真实状态再决定，绝不盲目重试。

3. 读路径是四层裁剪漏斗

Table.newScan() → 快照定位（branch/tag）→ 清单级：分区字段的 contains_null/lower/upper 摘要直接跳过整个 manifest → 文件级：InclusiveMetricsEvaluator 用每列 valueCounts/上下界丢文件 → 行组级：Parquet 行组统计与字典再剪 → 读行时用残余表达式兜底（分区元组算不掉的部分）。谓词到分区的投影靠 Transform.project（bucket/truncate/year/month/day/hour 各自实现 inclusive/strict 投影）。

4. 序列号：正确性的时间轴

V2 起 manifest 记 entry 的 data/file 两个序列号。新文件写 null，读者按 manifest 序号补齐——这让清单可以写一次、跨快照/跨重试复用。删除文件的生效条件是 dataSequenceNumber 大于数据文件序号，杜绝"旧删除追杀新写入"。增量读取（append/changelog）按快照 id 集合过滤 ADDED 条目并携带 changeOrdinal。

5. 删除三形态与 V3 演进

删除有三种落地：COW（DeleteFiles 重写清单丢文件）、位置删除（V2 文件 → V3 deletion vector/Puffin 位图，写侧强制）、等值删除（MoR，RowDelta + 读取时 DeleteFilter 施加）。V3 还带来行血缘（nextRowId/first_row-id）、Variant 类型、schema 默认值；V4 支持 Parquet manifest。维护动作全家桶：ExpireSnapshots（引用计数 + 增量/可达两种 GC 策略）、RemoveOrphanFiles（默认 3 天宽限的全量对比）、RewriteManifests/RewriteDataFiles（bin-pack/sort/zorder）、RemoveDanglingDeletes。

五、创新点

1️⃣ 把 ACID 搬到对象存储

文件不可变 + 指针原子交换，绕开对象存储不支持就地更新的物理限制，却在 S3 上实现完整快照隔离。

2️⃣ 隐藏的分区

分区是派生值（transform），查询按值过滤自动裁剪，用户再也不用手写"分区列"；分区演化按 spec-id 并存。

3️⃣ 时间旅行即树切换

branch/tag 是快照引用；回滚/时间旅行只是把指针指回旧子树，零数据拷贝。

4️⃣ 引擎无关的任务模型

FileScanTask/CombinedScanTask 统一 Spark/Flink 的输入分区，规划集中、执行分布。

5️⃣ REST 目录与远程扫描

requirements/updates 协议 + 多表事务端点 + 远程 scan planning（read.data-planning-mode=distributed），元数据密集型工作可下推服务端。

6️⃣ 可插拔安全删除

位置删除从文件形态（V2）进化到位图 DV（V3），写侧强制、读取按引用精确施加，避免全文件重扫。

七、建议学习路径

  1. 01 元数据树：手工建表后逐个打开 metadata.json / manifest-list / manifest（Avro）对照看。
  2. 02 裁剪漏斗：用 EXPLAIN + 扫描指标观察 manifest 被跳过的数量。
  3. 03 + 04：两个进程同时 INSERT，观察 CommitFailed 与重试日志。
  4. 05：分别跑 append、MERGE INTO、DELETE，对比生成的删除文件形态。
  5. 06：rollback 到旧快照后查询"已删除"的数据，再 expire + remove_orphan_files 看物理文件消失。
