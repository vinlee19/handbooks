01 · 项目全景与代码地图

设计哲学 → 仓库目录树 → 包内部结构 → 包管理体系（flit/零依赖/extras/CLI）→ CI 与发布。读完本篇，你应当对「代码在哪里、为什么这样分层」有完整的心智地图。

1.1 设计哲学：刻意「低抽象」

Burr 的 README 开宗明义（README.md:35）：让开发「会做决策的应用」变得简单，用简单的 Python 积木表达——不引入隐藏魔法。体现在工程上就是四条铁律：

  1. 零运行时依赖：pyproject.toml:25 中 dependencies = []。装上 apache-burr 内核不需要 pip 解析任何第三方包，State/Action/Application 都是纯标准库实现（dataclasses / abc / contextvars / inspect）。
  2. 显式状态契约：每个 action 必须声明 reads=[...] 和 writes=[...]，写未声明的键直接抛错（application.py:256-261）。这让 UI 能画出每个节点的数据签名，也让 fork/恢复变得安全。
  3. 位置即状态：执行游标 __PRIOR_STEP/__SEQUENCE_ID 存在 State 里而不是运行时对象里，「恢复执行」=「载入 State」，不需要单独的位置存储。
  4. 观测是插件不是内核：追踪、持久化、tracing 全部通过 Lifecycle Hook 注入（06 篇），删除它们核心引擎一行不改——这也是它从 DagWorks 商业产品平滑捐给 Apache 的结构基础。
名字由来：Burr 以美国政治家 Aaron Burr 命名——它最初是 Apache Hamilton（DAG 框架）的「状态管理外壳」，后来成长为独立框架，并保留了对 Hamilton 的一等集成（11 篇）。

1.4 包管理体系：flit + extras

为什么是 flit + 零依赖

pyproject.toml 用 flit_core 构建（纯 Python，无 C 扩展），项目名 apache-burr（PyPI 上的旧名 burr 通过 burr-redirect/ 壳包重定向）。基础安装没有任何依赖，Python ≥ 3.9。

所有可选能力都是 extras，按需安装：

pip install "apache-burr[start]"   # 新手全家桶：UI+示例+依赖
pip install "apache-burr[tracking]" # 客户端+服务端
pip install "apache-burr[graphviz]" # app.visualize()
pip install "apache-burr[developer]" # 全部

1.7 与同类框架对比

框架抽象核心与 Burr 的关键差异
LangGraph图 + 检查点深度绑定 LangChain 生态；Burr 保持框架无关、显式 reads/writes 契约
Temporal持久工作流重基础设施（专属集群）；Burr 是嵌入式库 + 可选本地 UI
LangChain链式组合隐式状态传递；Burr 状态显式、可控、可序列化
Hamilton数据流 DAG单次 DAG 执行无环；Burr 补充有环状态机；两者可互相嵌套（11 篇）

对比来源：README.md:151-158。Burr 独有组合：显式状态机 + 零依赖 + 内置开源监控 UI + 同时适用 LLM/非 LLM 场景。
