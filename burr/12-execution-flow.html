12.1 主角：hello-world-counter（全文仅 30 行有效代码）

from burr.core import Application, Result, State, default, expr
from burr.core.action import action
from burr.core.persistence import SQLLitePersister

@action(reads=["counter"], writes=["counter"])        # ← 03 篇：IO 契约声明
def counter(state: State) -> State:
    result = {"counter": state["counter"] + 1}
    print(f"counted to {result['counter']}")
    return state.update(**result)                    # ← 02 篇：不可变更新 SetFields

def application(count_up_to=10, partition_key="demo-user", app_id=None, ...):
    persister = SQLLitePersister("demos.db", "counter",
                                 connect_kwargs={"check_same_thread": False})  # ← 07 篇
    persister.initialize()
    return (
        ApplicationBuilder()
        .with_actions(counter=counter, result=Result("counter"))   # 内置动作
        .with_transitions(
            ("counter", "counter", expr(f"counter < {count_up_to}")), # 自环！
            ("counter", "result", default))              # ← 03 篇条件 + 05 篇边
        .with_identifiers(partition_key=partition_key, app_id=app_id)
        .initialize_from(persister, resume_at_next_action=True,
                         default_state={"counter": 0},
                         default_entrypoint="counter")    # ← 07 篇断点恢复
        .with_state_persister(persister)
        .with_tracker(project="demo_counter")              # ← 09 篇 LocalTrackingClient
        .build())                                          # ← 05 篇装配流水线

if __name__ == "__main__":
    app = application(app_id="a7c8e525-...")   # 固定 app_id → 可断点恢复
    action, result, state = app.run(halt_after=["result"])  # ← 04 篇执行循环
    app.visualize("statemachine.png", include_conditions=True)

12.4 进阶形态：多模态聊天机器人怎么用上这些机制

代码里的高级模式（05 篇图 5-3 的实现）

  • bind 复用：同一个 chat_response 动作绑定三种 prompt 上下文（image/code/answer），构建出三个图节点；
  • 条件扇出：decide_mode 用 LLM 输出 mode 字段，四条 when(mode=...) 边按声明顺序路由；
  • 流式回答：response 相关动作用 @streaming_action，FastAPI 侧 astream_result 把块直接转发给前端 SSE（examples/streaming-fastapi）；
  • 追踪即持久化：initialize_from(tracker, ...) 直接拿 LocalTrackingClient 当初始化器——聊天历史按 app_id 续接；
  • span 标注：动作内声明 __tracer，把「LLM 调用」「审核调用」开成子 span，UI 时间线层次分明。

12.6 动手验证清单

  1. pip install "apache-burr[start]" && burr-demo —— 打开 http://localhost:7241 对照 10 篇找视图；
  2. python examples/hello-world-counter/application.py —— 跑两次（同 app_id），在 UI 看断点续跑（07 篇）；
  3. cat ~/.burr/demo_counter/*/log.jsonl —— 对照 09 篇事件模型逐行读懂；
  4. 给 counter 加一个 PostRunStepHook 打印耗时（06 篇），验证钩子时机；
  5. 把 expr(f"counter < {n}") 改成 safe_expr("counter < 10")，再试试给 safe_expr 喂 "().__class__" 观察拦截（03 篇）；
  6. 跑 examples/multi-modal-chatbot，在 UI 里看 bind 出的三节点与 span 树（11 篇）。
结语：读源码的终点不是「知道每个函数」，而是能在脑中运行整个系统。如果你能不看文档回答——「halt_before 命中时 stream_result 为什么返回空容器」「failed 状态为何从 entrypoint 重试」「children.jsonl 为什么写在父目录」——那这套 13 篇的剖析就完成它的使命了。
