10 · React 遥测 UI：把执行历史变成可探索的产品

源码：telemetry/ui/（React 18 + TypeScript + Vite 6 + Tailwind）。这一篇覆盖：技术栈与路由、五个核心视图、API 客户端生成、构建发布链路、demo 数据机制。

10.1 技术栈与工程结构

选型一览

库用途
React 18 + TypeScript + Vite 6主体（2025 年从 CRA 迁移到 Vite，commit 7f7fe34a）
reactflow + dagre状态机图视图与自动布局

API 客户端是「生成」的

telemetry/ui/scripts/client-gen.sh 启动后端取 openapi.json，用 openapi-typescript-codegen 生成 src/api/（核心 services/DefaultService.ts 约 785 行）。前后端契约由 FastAPI 的 pydantic schema 单向推导，永远不会漂移。

dev 体验：vite.config.ts 把 /api 代理到 localhost:7241，前端热更新 + 后端本地跑。

10.2 路由与视图结构

10.3 两个最有代表性的视图

GraphView：状态机的活地图

  • 数据源：应用的 application_logs 里第一步携带的完整图结构（graph.json 内容）+ 每步的 action 名；
  • reactflow 渲染节点/边，dagre 自动布局；条件边显示条件名、虚线样式（与 graphviz 渲染约定一致）；
  • 当前步骤高亮：读取最新 step 的 action，把对应节点着色——轮询刷新时你能实时看到指针在图上移动；
  • 节点点击 → 联动 StepList 定位到该动作的历史步骤。

StepList / InsightsView：调试主战场

  • StepList（约 1864 行）按 sequence_id 倒序渲染每步：开始/结束时间、inputs 摘要、span 树展开、流式块计数、异常红标；
  • DataView 展示该步前后的完整 state（JSON diff 视角）与 result；
  • InsightsView 汇总每步的 LLM 调用：模型、token 数、按 src/components/common/modelCost.tsx（内置价格表 + scripts/model_costs.json）折算成本；
  • AnnotationsView 写注释 → annotations API → 落盘 annotations.jsonl。

10.4 构建 → 打包 → 服务链路

10.5 demo 数据与内嵌示例

UI 首次体验需要数据，Burr 的做法是「把示例的运行结果也打包」：

  • burr/tracking/server/demo_data/ 内置 4 个预生成项目：demo_counter / demo_chatbot / demo_chatbot_with_traces / demo_conversational-rag——每个都是标准三件套（graph.json/metadata.json/log.jsonl），与真实运行产物格式完全一致；
  • burr-demo 命令把它们拷入 ~/.burr 后启动服务；
  • server 还挂了 demo 路由（/api/v0/{chatbot,email_assistant,streaming_chatbot,deep_researcher,counter}），动态 import 包内 burr/examples/ 的五个示例应用，供 UI 的「演示」入口现场跑一个新应用。
源码学习技巧：demo_data 是理解追踪数据格式的最佳样本——直接 cat ~/.burr/demo_counter/*/log.jsonl 对照 09 篇的事件模型，十分钟读懂全部字段。

10.6 前后端交互时序

本篇要点：① UI 是独立 Vite 工程，构建产物在打包期汇入 wheel、由 FastAPI 托管；② API 客户端由 OpenAPI 生成，契约零漂移；③ 核心页面七个视图围绕「一次全量日志请求 + 轮询」运转；④ demo 数据与真实数据同格式——学数据模型先看 demo_data。
