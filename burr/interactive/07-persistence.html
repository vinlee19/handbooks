07 · 持久化与断点恢复：可恢复执行的全部机制

源码：burr/core/persistence.py（725 行）+ burr/integrations/persisters/。因为位置活在 State 里（04 篇），持久化只需要保存「一份序列化 State + 位置元数据」就能实现完整的时间旅行。

7.1 协议：读/写两个小接口

写侧 BaseStateSaver（:112）

save(partition_key, app_id,
     sequence_id,      # 第几步
     position,         # 哪个 action
     state,            # 序列化后的 State
     status)           # "completed"|"failed"
initialize() / is_initialized()

每步一条记录（不是覆盖），天然形成逐步快照链——UI 的时间滑杆、fork 到任意历史点都靠它。

读侧 BaseStateLoader（:54）

load(partition_key, app_id,
     sequence_id=None
     ) -> PersistedStateData | None
list_app_ids(partition_key)

sequence_id=None 表示取最新一条。返回的 PersistedStateData（TypedDict，:44）含 partition_key / app_id / sequence_id / position / state / created_at / status 七个字段。

合体与异步孪生

BaseStatePersister = BaseStateLoader + BaseStateSaver（:202）；每个接口都有 AsyncBase* 孪生（:83/:157），并约定 is_async() 判别——Builder 在 build 时据此强制 sync 应用配 sync persister、async 应用配 async persister（application.py:2700-2705, 2594-2599）。

7.5 使用范式与陷阱

标准三件套

p = SQLLitePersister("app.db", "myapp")
p.initialize()                 # 建表（幂等）
ApplicationBuilder()\
  .with_identifiers(# 定位身份
    partition_key="user-42",
    app_id="session-abc")\
  .initialize_from(p,          # 读
    resume_at_next_action=True,
    default_state={"counter": 0},
    default_entrypoint="counter")\
  .with_state_persister(p)\    # 写
  .build()

易踩的坑

  • 忘了 initialize()：表不存在，首步 save 即失败（async 版会在 build 时直接 RuntimeError，:2606-2610）。
  • identity 漂移：app_id 用随机 uuid 又想断点恢复——两次构建 uid 不同，永远查不到记录。要恢复必须显式固定 app_id。
  • 大对象状态：每步全量序列化整份 State；大 DataFrame 应注册 serde 压缩，或把重数据放外部存储、State 里只留引用。
  • 多进程写同一 SQLite 文件：注意连接参数（如 check_same_thread=False + WAL）。
本篇要点：① 协议极小：load(三参)/save(六参)，返回七字段快照记录；② 持久化 = PersisterHook，异常步骤也留痕（failed）；③ 恢复在 build() 完成：completed 续下步、failed 重试当前步；④ 快照链天然支持 fork 时间旅行；⑤ 内置 SQLite 开箱即用，6 种数据库实现按 extras 安装。
