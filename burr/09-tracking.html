09 · 追踪客户端与服务端：从 JSONL 到浏览器

源码：burr/tracking/（client.py 680 行 / s3client.py 513 行 / server/ 全目录）。设计关键词：文件即数据库（本地模式）、追加式 JSONL、客户端与服务端共享同一目录。

9.1 LocalTrackingClient：把钩子写成文件

身份与文件契约

# tracking/client.py:155-172
class LocalTrackingClient(SyncTrackingClient, BaseStateLoader):
    GRAPH_FILENAME    = "graph.json"
    METADATA_FILENAME = "metadata.json"
    LOG_FILENAME      = "log.jsonl"
    CHILDREN_FILENAME = "children.jsonl"
    DEFAULT_STORAGE_DIR = "~/.burr"

它同时实现 BaseStateLoader —— 追踪数据可以反过来当状态初始化器：initialize_from(tracker, ...) 直接从 log.jsonl 恢复（hello-world-counter 就这么用）。

9.5 细节与陷阱

值得注意的实现细节

  • client 的 __getstate__/__setstate__ 把打开的文件句柄排除在 pickle 外——client 对象可以随应用一起被 pickle/并行传递（client.py 尾部）。
  • copy_from / fork_app 支持整目录复制出分支应用；get_logs/load 类方法用于离线分析。
  • 流式观测的 post_stream_item 只记录首个块（体积考虑），UI 显示「有流、首块延迟」。
  • S3 客户端的 unique_ordered_prefix 按时间分层，保证 S3 list 的时间有序性。

常见问题

  • UI 看不到数据？确认 server 的 burr_path（env）与 client 的 storage_dir 指向同一目录；project 名拼写一致。
  • 并发写损坏？log.jsonl 是单写者追加（每个 app 目录一个写者）；children.jsonl 有 flock。多进程写同一 app_id 不受支持——那是 fork/spawn 该做的事。
  • 状态反序列化失败？检查 serde 注册（02 篇）——服务端只需展示 JSON，通常无需还原类型。
  • 匿名遥测？已按 ASF 政策移除；burr/telemetry.py 只是兼容桩。
本篇要点：① 追踪客户端 = 钩子集合 → 追加式 JSONL；graph.json/metadata.json 一次性写、log.jsonl 持续追加、children.jsonl 反范式血缘；② 服务端默认 LocalBackend 直接读同一目录——「文件即 API 的数据源」；③ 生产用 S3+SQS+SQLite 索引的同构扩展；④ 客户端兼任 BaseStateLoader，追踪数据可直接用于断点恢复。
