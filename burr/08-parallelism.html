08 · 并行执行：把子状态机跑进线程池/事件循环/集群

源码：burr/core/parallelism.py（895 行）+ burr/integrations/ray.py。Burr 的并行哲学：一个「并行动作」在内部生成 N 个真正的子 Application，交给执行器并发跑完，再 reduce 回主状态。

8.4 SubGraphTask 的构建细节

_create_app_builder（:106-142）

每个任务在执行时才构建子应用（惰性），关键注入：

  • with_spawning_parent(context) —— 记血缘；
  • tracker 级联 / persister copy 级联；
  • initialize_from(state_initializer) 用任务自带的状态切片；
  • entrypoint / halt 来自 RunnableGraph。

为什么先 wipe 私有键

主 State 里的 __PRIOR_STEP/__SEQUENCE_ID 若流入子应用，会让子应用「以为」自己跑到某一步。并行动作在生成任务前统一 wipe（:254 的第一步），保证子应用从干净位置开始。

对应地，04 篇的 _state_update 也会剥离子应用带回的私有键——两边夹击，游标永不被污染。

8.5 使用范式

from burr.core import action, State
from burr.core.parallelism import map_reduce_action, MapActions

# 写法一：工厂函数（常用）
parallel_review = map_reduce_action(
    readies=["question"], writes=["reviews"],     # 主 IO 契约
    action_to_map=review_action,                  # 要并发的动作
    num_actions=3,                                # 并发 N 份
    reduce=lambda state, states: state.append(    # 收敛
        reviews=[s["review"] for s in states]),
)

# 写法二：继承 TaskBasedParallelAction 自定义 tasks() 生成器
class MyFanOut(TaskBasedParallelAction):

        for i in range(state["n"]):
            yield SubGraphTask(RunnableGraph(my_subgraph, entrypoint="a",
                                 halt_after=["done"]),
                               inputs={"k": i}, name=f"task-{i}")

本篇要点：① 并行的单位是「真子 Application」（SubGraphTask），不是裸函数——因此天然继承观测/持久化/血缘；② 执行插槽是 Executor 协议：默认线程池、async 走 gather、Ray 可插拔；③ 状态切片与 reduce 完全由用户定义，Map* 三兄弟覆盖常见形态；④ 私有键双向剥离保证游标安全；⑤ SQLite 这类不可共享资源靠 BaseCopyable.copy() 级联。
