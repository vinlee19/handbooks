4.2 游标机制：位置活在 State 里

两个哨兵键

# application.py:85-86
PRIOR_STEP   = "__PRIOR_STEP"   # 上一个动作名
SEQUENCE_ID  = "__SEQUENCE_ID"  # 步计数器

每步结束时 _update_internal_state_value（application.py:1010-1019）把刚执行的动作名写进 __PRIOR_STEP；每步开始前 _increment_sequence_id（:2109-2113）自增计数。

决定下一步

def get_next_action(self):          # :2034
    return self._graph.get_next_node(
        self._state.get(PRIOR_STEP),
        self._state, self.entrypoint)

推论（设计精髓）

  • 恢复 = 载入 State：进程崩溃后重建 Application 并灌入持久化的 State，__PRIOR_STEP 让执行精确落在断点之后；
  • 对账有主键：__SEQUENCE_ID 让 log.jsonl 事件、数据库行、span 全部能对齐到「第几步」；
  • 游标受保护：归并时动作写下的 __ 私有键会被剥离（02 篇 _state_update），动作无法篡改位置；
  • reset_to_entrypoint() 的实现就是删掉 __PRIOR_STEP（:1005-1008）——回到起点=丢失位置。

4.5 输入处理与依赖注入

_process_inputs（application.py:1021-1072）在每步执行前对入参做四件事：

  1. 拒绝 __ 前缀：用户传入双下划线键直接 ValueError——那是框架保留位；
  2. 过滤：只保留 action 声明的 required/optional inputs，多余的丢弃并打 debug 日志；
  3. 注入：缺失的输入若命中 _dependency_factory（__tracer/__context），现场制造注入；
  4. 报错：仍缺失则抛出带「FILL ME IN」模板的详细错误，直接告诉你怎么改调用。
为什么用 __ 前缀？ Python 会把签名中的 __context 名字修饰（name-mangle）成 _ClassName__context，引擎用 _remap_dunder_parameters（application.py:130-158）在调用前把参数名改写回去——这是个冷知识级细节，读码时容易困惑。

4.6 深挖 _state_update：归并与删除语义

为什么需要归并

函数式动作直接返回完整 State，其中可能夹带：未声明的键（禁止）、该删的键（允许删除！）、__ 私有键（必须剥离）。_state_update（application.py:199-230）三步处理：

① wipe 掉 modified 里的全部 __ 私有键
② 对比新旧键集求出 deleted_keys
   （旧有新无 且 非 __ 前缀）
③ merge 后再 wipe(deleted_keys)

这样「action 返回的 State 缺了个键」就被解释为删除，而不是丢数据——issue #28 的修复。

写入的双重校验

_run_reducer（application.py:243-263）：

  • extra_keys = 新增键 − reducer.writes → 抛「attempted to write to keys that it did not declare」；
  • _validate_reducer_writes：声明的 writes 没写全也抛错（:233-240）。

效果：动作的 IO 契约是强制的，UI 才能可靠地展示每个节点的数据签名，状态永远可推理。

4.7 fork 与 spawn：应用的血缘

4.8 异步语义的三个细节

1. 混合动作

astep 遇到同步动作时不是硬 await，而是回调 _step(_run_hooks=False)（:1118），再补发 async 钩子——避免同一事件钩子双发。

2. 异步校验

validate_correct_async_use()（:2160 附近）阻止在事件循环里调同步 run（反之亦然），给出明确改法提示。

3. aiterate 无返回值

async 生成器语言层面不能 return value，所以 arun 自己累加 prior_action/result（:1382-1384），而不复用 _return_value_iterate 的 StopIteration 通道。

本篇要点：① Application 只有 _state 一个可变字段；位置与步数都是 State 的键；② run=排空 iterate=循环 step，所有入口共享 halt 解析与恰好一次的 execute-call 钩子；③ _step 的骨架 = 寻址→前置钩子→执行→盖游标→提交→finally 后置钩子；④ 依赖注入只认 __tracer/__context，上下文靠 contextvars 穿透任意深度；⑤ 写入契约（未声明键报错、声明必写、删除语义）让状态永远可推理。
