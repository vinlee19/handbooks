05 · Graph 与 ApplicationBuilder：从声明到可运行

源码：burr/core/graph.py（385 行）+ burr/core/application.py:2201-2875（Builder）。图是纯数据结构，Builder 是「收集器 + 校验器 + 装配器」——本篇讲清一次 build() 里发生的全部事情。

5.1 图模型：Graph / Transition / Condition

Graph（graph.py:114）是一个 dataclass，只有两个公开字段 actions: List[Action] 与 transitions: List[Transition]，全部「索引」都在 __post_init__（:122-126）一次建好：

  • _action_map：名字 → Action；
  • _adjacency_map：源动作名 → 有序列表 [(目标名, Condition), ...]（:128-135）——有序是条件路由的根基；
  • _action_tag_map：tag → 动作列表（配合 halt_after=["@tag:..."]）。

Transition（:33-38）= from_ + to + condition 三元组。图本身不含状态、不可执行——它是纯粹的静态拓扑；执行所需的 entrypoint 由外层 ApplicationGraph（application.py:599-607）补充。

5.3 GraphBuilder：轻量校验器

三个收集方法

  • with_actions(*args, **kwargs)（graph.py:286-312）：kwargs 键作为动作名，经 create_action 统一「摘属性 + 命名」；重名直接报错。
  • with_transitions(*tuples)（:314-345）：支持 (from, to)（自动 default）与 (from, to, condition)；from 还可以是列表实现多源合流（fan-in）。
  • with_graph(graph)（:347-364）：合并已有图（组合复用大图）。

build() 的校验

  • _validate_actions（:41-54）：至少一个动作、名字唯一；
  • _validate_transitions（:57-79）：边的两端必须都在动作集里；同一源只允许一条 default。
不校验的事：可达性（存在孤儿动作不报错）、死锁、缺少终点——图保持最大自由度，执行期的 halt 条件才是「终点」的真正来源。
