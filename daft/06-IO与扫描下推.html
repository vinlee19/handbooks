1. 解决了什么问题

「读 100 行」对用户而言是一个 SQL LIMIT 100,但底层要做的事完全不同:

              用户视角                                    存储视角(S3 + Parquet)
              -----------                               -----------------------
  daft.read_parquet("s3://b/year=2024/*")               1. LIST  (s3://b/year=2024/*  → 文件清单)
    .where("amount > 100")                              2. GET   (每个文件 footer 8B + footer N kB)

    .collect()                                          5. 字节范围合并/拆分(coalesce / split)

谓词 + 投影下推到 ScanTask 不读不需要的列、不需要的行组

字段 谁会设? 谁会用?
filters PushDownFilter 规则 行组裁剪 + 解码后 filter
partition_filters scan operator(从 Hive 风格路径推断) LIST 阶段直接跳过分区
columns PushDownProjection 规则 Parquet column-chunk 选择
limit PushDownLimit 规则 Source 提前终止
sharder PushDownShard 规则 多 worker 切分输入
pushed_filters SupportsPushdownFilters 已被存储侧消化,不需要再 evaluate
aggregation PushDownAggregation 规则 行组级 partial count/sum/min/max

SupportsPushdownFilters trait(pushdowns.rs:10):

pub trait SupportsPushdownFilters {
    fn push_filters(&self, filter: &[ExprRef]) -> (Vec<ExprRef>, Vec<ExprRef>);
    //   → 返回 (可下推的, 必须留在 plan 上的)
}

命名细节:filters 字段是"全部当前 filter",pushed_filters 是"存储侧已消化掉的子集"。这两组不同,因为有些谓词可被存储部分使用(如 partition col)但 plan 还得保留(残余 column 仍要 filter)。

4.1 IOClient::get_source_and_path —— URL 路由

src/daft-io/src/lib.rs:233-335(节选):

pub async fn get_source_and_path(&self, input: &str)
    -> Result<(Arc<dyn ObjectSource>, String)>
{
    let resolved = resolve_url_alias(input, &self.config);
    let (source_type, path) = parse_url(&resolved)?;

    // 双重检查 + 写锁(避免重复初始化 backend client)
    if let Some(client) = self.source_type_to_store.read().await.get(&source_type) {
        return Ok((client.clone(), path.to_string()));
    }
    let mut w_handle = self.source_type_to_store.write().await;
    if let Some(client) = w_handle.get(&source_type) {
        return Ok((client.clone(), path.to_string()));
    }

    let new_source = match &source_type {
        SourceType::File => LocalSource::get_client().await? as Arc<dyn ObjectSource>,
        SourceType::Http => match url.domain() {
            Some("huggingface.co") => HFSource::get_client(...).await?,  // 特判
            _ => HttpSource::get_client(...).await?,
        },
        SourceType::S3 => S3LikeSource::get_client(&self.config.s3).await?,
        // ...
        SourceType::OpenDAL { scheme } => { /* 见下 */ }
    };
    w_handle.insert(source_type, new_source.clone());
    Ok((new_source, path.to_string()))
}

OpenDAL 是兜底:任意 URL scheme(cos://, oss://, obs:// 等)只要 IOConfig.opendal_backends[scheme] 有配置,都能跑(lib.rs:304-328)。COS 有特别处理——会从 URL 提取 bucket 自动注入 OpenDAL config,这样用户写 cos://my-bucket/foo.parquet 不用手动填 bucket。

4.2 GetResult::bytes() —— 重试与续传

src/daft-io/src/object_io.rs:79-130:

const NUM_TRIES: u64 = 3;
const JITTER_MS: u64 = 2_500;
const MAX_BACKOFF_MS: u64 = 20_000;

let mut result = collect_bytes(stream, size, permit).await;
for attempt in 1..NUM_TRIES {
    match result {
        Err(SocketError {..} | UnableToReadBytes {..}
            | UnableToOpenFile {..} | MiscTransient {..})
            if let Some(rp) = &retry_params => {
            let jitter = rand::rng().random_range(0..((1 << (attempt - 1)) * JITTER_MS));
            let jitter = jitter.min(MAX_BACKOFF_MS);
            tokio::time::sleep(Duration::from_millis(jitter)).await;
            // 重新发起 GET
            get_result = rp.source.get(&rp.input, rp.range.clone(), rp.io_stats.clone()).await?;
            if let Stream(stream, size, permit, _) = get_result {
                result = collect_bytes(stream, size, permit).await;
            }
        }
        _ => break,
    }
}
sequenceDiagram participant App participant GR as GetResult::bytes() participant Net as ObjectSource::get participant S3 App->>GR: bytes() GR->>Net: 第一次 collect_bytes(stream) Net->>S3: HTTP GET (range) S3-->>Net: 200 + 部分流 Net-->>GR: SocketError(中断) GR->>GR: jitter ∈ [0, 2_500ms),sleep GR->>Net: 重发(attempt=1) Net->>S3: HTTP GET (range) S3-->>Net: 200 + 完整流 Net-->>GR: Bytes GR-->>App: Ok(bytes)

注意 jitter 公式 (1 << (attempt - 1)) * JITTER_MS 是指数退避基数,实际值在 [0, 2_500 << (attempt-1)) 区间随机,再 cap 到 MAX_BACKOFF_MS = 20_000ms。

with_retry(object_io.rs:132-141)产生的 ResumableByteStream(object_io.rs:147-240)更进一步——每读到 n 字节就把 delivered 累加,失败重试时构造新的 range = original.start + delivered,断点续传而非重读。

4.4 字节范围合并/拆分案例

原始(假设要读 3 列 × 3 行组 = 9 个 column-chunk):
col_a/RG0: [   100 ..    300]    72KB
col_a/RG1: [   500 ..    700]    74KB
col_a/RG2: [   900 ..   1100]    71KB
col_b/RG0: [  2000 ..   2150]    63KB
col_b/RG1: [  2200 ..   2350]    62KB
col_b/RG2: [  2400 ..   2550]    61KB
col_c/RG0: [800000.. 900000]   400KB
col_c/RG1: [900000..1000000]   400KB
col_c/RG2: [1000000..1100000]  400KB

CoalescePass(max_hole_size=200, max_request_size=2MB):
[100..1100]                    1 个 GET (含 3 个间隙的 col_a)

5. 怎么优化的:四个技术点

5.1 行组级裁剪 vs 解码后 filter

裁剪只能对 ColumnRangeStatistics::supports_dtype 为 true 的列生效。Image/Tensor 等多模态列没有 min/max,只能走 "下载 + 解码 + filter"。

5.2 ReadPlanner 的合并/拆分
