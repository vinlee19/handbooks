1. 解决了什么问题

1.1 一句话定位

Daft 是一个 Rust 内核 + Python API 的 多模态 + 流式 + 可分布式 的 DataFrame / 查询引擎。

它要同时做四件事(任何一件单拿出来都不算新,但合在一起就是新空间):

  1. 像 polars 那样:列存 + 向量化 + 查询优化,单机就能打过 pandas
  2. 像 spark 那样:能横向扩到集群跑 PB 级
  3. 像 Ray Data 那样:把 image / tensor / URL / file 当一等公民
  4. 像 duckdb 那样:嵌入 Python 进程零运维

6.2 一次运行,8 站快照

flowchart TB S1["Stage 1: Python<br/>daft.read_parquet → DataFrame"] -->|惰性| S2 S2["Stage 2: LogicalPlanBuilder<br/>Source→Filter→Project→Limit→Sink"] -->|optimize()| S3 S3["Stage 3: Optimizer<br/>下推 Filter→Source<br/>下推 Limit→Source<br/>下推 Project→Source"] --> S4 S4["Stage 4: LocalPhysicalPlan<br/>PhysicalScan + Limit"] --> S5 S5["Stage 5: Swordfish<br/>build_pipeline ⇒ Source 算子"] --> S6 S6["Stage 6: ScanTask<br/>Pushdowns { filter, columns, limit }"] --> S7 S7["Stage 7: ReadPlanner<br/>S3 GET 字节范围(已合并)"] --> S8 S8["Stage 8: yield MicroPartition<br/>→ Python iterator"]

关键观察:Stage 3 的下推会让 Stage 6 的 Pushdowns 同时带上 filter / columns / limit 三种;Stage 7 的 ReadPlanner 因此只下载 必要列、必要行组、必要字节。这就是 Daft 在多模态场景下"不读图就能裁掉无关行"的根因。
