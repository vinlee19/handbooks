Delta Lake 总体架构：以事务日志为唯一真相

Delta Lake 的全部魔法浓缩成一句话：一张表就是一个事务日志目录（_delta_log）。提交 = 追加一个 JSON 文件，读取 = 重放日志构建快照。本手册基于 spark/src/main/scala/org/apache/spark/sql/delta 的逐模块分析，把这条主线拆开看透。

01要解决什么问题

对象存储上的 Parquet 目录没有事务：并发写互相覆盖、更新只能全量重写、无法回滚。Delta Lake 用预写日志（Write-Ahead Log）解决：每次提交是一个原子可见的 JSON 文件，记录「新增了哪些文件、删除了哪些文件、元数据如何变化」。

这条设计让 Delta 用最朴素的文件语义获得了 ACID，也让 Time Travel、Schema 演进、审计成为免费副产品。
