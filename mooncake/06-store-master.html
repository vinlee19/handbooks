CHAPTER 06 · MASTER SERVICE

Master 深度剖析：地址簿、裁判与回收站

MasterService（mooncake-store/src/master_service.cpp，5000+ 行）是 Store 的大脑：1024 个元数据分片、三段式写协议、租约与软/硬 pin、两遍淘汰扫描、副本放置策略、fork 快照与 HA 数据源。本章逐一拆开这些机制。

6.1内部结构：分片、线程与锁序

Master 的并发模型是"分片 + 专用线程"：kNumShards = 1024（master_service.h:1650）把所有 key 的元数据按哈希打散到 1024 个 MetadataShard（各持一把 SpinLock），读写互不阻塞。类注释明确写出锁获取顺序（避免死锁的圣经）：client_mutex_ → metadata_shard → segment_mutex_。四个常驻线程各司其职：淘汰线程（10ms 周期）、快照线程、任务管理、客户端探活。

图 6-1MasterService 内部结构：1024 分片 + 段管理 + 四类常驻线程

6.2三段式写协议

一次 Put(key, slices, config) 在 Master 视角分三步。PutStart 检查 key 不存在/未过期后，为 ReplicateConfig 要求的每个副本分配空间（内存副本在某个 segment、磁盘副本生成 file_path），登记 processing_keys 并返回副本描述符列表；客户端随后并行地把数据搬到位（RDMA 直写内存副本、写本地盘的 DISK 副本）；最后 PutEnd 校验写入者身份并把副本标记 COMPLETE、授予初始租约。任一步失败，PutRevoke 触发 RAII 级回滚——副本空间随 ObjectMetadata 析构自动释放。

图 6-2三段式写：Master 锁定空间与副本位置 → 数据点对点直写 → 提交/回滚

6.3租约体系与软/硬 pin

缓存池最难的问题是"什么时候能删"。Mooncake 用一组时间参数把这个问题变成纯机械判断：

参数默认量级作用
读租约（lease）秒级（默认 5s 档）GetReplicaList 返回时隐式授予；租约期内对象禁止淘汰，保证"读到的数据此刻还在"
软 pin（soft pin）30 分钟档with_soft_pin=true 的高价值前缀：期内禁止淘汰（第一遍扫描不动它），过期后进入可淘汰集合
硬 pin（hard pin）永久with_hard_pin=true：永不淘汰（如 system prompt 常驻层）
Put 超时 discard / release30s / 600s 两档写卡死后回收 processing 副本的时限

6.4副本放置策略

ReplicateConfig（include/replica.h）控制放置：replica_num（副本数）、with_soft_pin/with_hard_pin、preferred_segments（偏好段，常用于把副本钉到某类节点）、prefer_alloc_in_same_node（读亲和：副本尽量同节点，读时本地命中率高）。分配时 AllocationStrategy 三个实现择一：Random（随机段）、FreeRatioFirst（剩余比例最高的段优先，天然均衡）、Cxl（优先 CXL 内存池段）。开启磁盘副本（use_disk_replica）后 PutStart 额外创建一个 DISK 副本，file_path 由 key 哈希到根目录树。

6.5快照与 OpLog：HA 的数据基础

Master 的元数据要能被 standby 重建，靠"快照基线 + OpLog 增量"两层：

  • 快照：快照线程周期 PersistState() —— fork 子进程在无锁瞬间序列化 1024 个 shard（MetadataSerializer，msgpack），上传到 SnapshotObjectStore（本地目录或 S3），catalog 记录到 embedded/redis 的 SnapshotCatalogStore；启动时 RestoreState() 反向恢复。fork 的妙处：父进程零停顿、数据一致性由 COW 天然保证。
  • OpLog：快照之后的增量以条目（sequence_id / op_type / key / payload / checksum / prefix_hash）追加进 OpLogManager，经 EtcdOpLogStore（或共享盘 LocalFs）传播；PUT_END/PUT_REVOKE/REMOVE 三类操作覆盖全部状态变化，REMOVE 走强持久（AppendAndPersist）。
图 6-4快照 + OpLog：fork 快照做基线，etcd watch 做增量，lag 检查做提升闸门
读源码最容易迷路的三处：① MetadataAccessorRW 的隐式清理逻辑（访问即修复）；② 淘汰与 offload 的耦合（先下沉后释放，offload_force_evict_ 兜底）；③ discarded_replicas_ 的延迟释放（防"刚释放立即被重用导致在途 RDMA 写坏数据"）。
