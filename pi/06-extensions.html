扩展系统：进程内的钩子网络

扩展就是一个导出 (pi) => void 工厂函数的 TypeScript 文件——没有独立进程、没有 RPC、没有沙箱接口。它通过 jiti 被直接 import 进 pi 进程，拿到一个 1,727 行类型定义的 ExtensionAPI：34 种事件订阅、6 类注册、十几个动作。pi 自己没有的权限系统，官方推荐就是用扩展写确认门。

1发现与加载

扩展从四个来源发现，按顺序加载（后加载的可覆盖命令同名者会收到错误提示）：

packages/coding-agent/src/core/extensions/loader.tsL436-464
async function loadExtensionModule(extensionPath: string, cacheToken?: ExtensionCacheToken) {
  if (isCurrentCacheToken(cacheToken)) {
    const cachedFactory = extensionCache.get(extensionPath);   // reload 时命中缓存
    if (cachedFactory) {
      return cachedFactory;
    }
  }

  const jiti = createJiti(import.meta.url, {
    moduleCache: false,
    // Bun uses modules embedded in the executable. Source TypeScript reuses the
    // host-resolved modules and root tsconfig paths. Built Node uses dist aliases.
    ...(isBunBinary
      ? { virtualModules: VIRTUAL_MODULES, tryNative: false }
      : isTypeScriptSourceRuntime
        ? { virtualModules: VIRTUAL_MODULES, tsconfigPaths: true }
        : { alias: getAliases() }),
  });

  const module = await jiti.import(extensionPath, { default: true });
  const factory = module as ExtensionFactory;
  if (typeof factory !== "function") {
    return undefined;
  }
  if (isCurrentCacheToken(cacheToken)) {
    extensionCache.set(extensionPath, factory);
  }
  return factory;
}

3拦截语义：谁能改什么

带 Result 的事件不只是通知。分发器按扩展加载顺序依次调用 handler，合并语义各不相同——例如 context 事件把消息数组 structuredClone 后逐个传给扩展改写，而 tool_call 的 block 一票否决立即短路：

packages/coding-agent/src/core/extensions/runner.tsL932-953 · tool_call 分发
async emitToolCall(event: ToolCallEvent): Promise<ToolCallEventResult | undefined> {
  const ctx = this.createContext();
  let result: ToolCallEventResult | undefined;

  for (const ext of this.extensions) {
    const handlers = ext.handlers.get("tool_call");
    if (!handlers || handlers.length === 0) continue;

    for (const handler of handlers) {
      const handlerResult = await handler(event, ctx);

      if (handlerResult) {
        result = handlerResult as ToolCallEventResult;
        if (result.block) {
          return result;      // 一票否决：不再询问后续扩展
        }
      }
    }
  }

  return result;
}

被 block 的工具调用不会消失：循环为它生成一条错误 ToolResultMessage（reason 就是扩展给的 reason），模型下一轮能看到"被拒绝"及其原因并调整行为。terminate 语义（03 篇）在此生效：整批结果都 terminate 才提前终止循环。

5ctx.ui 与两个进程的边界

扩展调 ctx.ui.confirm() 时发生了什么取决于运行模式：interactive 模式直接弹真组件并 await 用户选择；RPC/无头模式下，这个调用被序列化成 extension_ui_request 事件发给宿主进程，宿主渲染自己的 UI 后回 extension_ui_response，扩展侧的 await 才返回。这就是 0.84.4 新增 ui_prompt_start/ui_prompt_end 事件的原因：宿主集成需要区分"agent 在推理"与"agent 在等我点按钮"这两种完全不同的等待。

6生态速览

examples/extensions/ 下有 70+ 个官方示例：permission-gate（确认门）、plan-mode、subagent（派生子会话）、sandbox、custom-compaction（接管压缩）、doom-overlay（在编辑器上玩 DOOM，展示 custom overlay 能力）等。pi 自身只内置一个隐藏扩展：llama.cpp 本地模型对接（src/extensions/llama/，含 /llama 命令、huggingface 拉取、provider 注册）——它本身就是一个"扩展能做什么"的官方标杆。
